# Vertex layers for the shader editor

Worktree `/home/banon/projects/er-mods-rs/.worktrees/er-shader-vertex`, branch `feat/er-shader-vertex`, made from `feat/er-shader-editor` at `72ef6a9b`. Paths are relative to that root unless written absolute. This extends `docs/plans/er-shader-editor.md`, called "the editor plan" below; its sections are cited as E1, E7.6 and so on.

The goal is the user's: a layer that moves geometry the way a vertex shader would, for example to make things wobble. Today every layer runs inside one of five full-screen pixel passes (lighting AO and AO+SSR, combined albedo, tonemap, tonemap LUT), so nothing can move a mesh. E8.1 duplicates G-buffer draws only to write masks.

Writing this plan built nothing, launched nothing and committed nothing. Three researchers reported (FACTS, GS, PATCH). This plan decides between them; where they disagreed, the judge checked the evidence again, and section 2 says what was checked.

## 1. Decisions

| Question | Decision | Why |
|---|---|---|
| How geometry moves | **Patch the game's own vertex shaders in DXIL.** The layer's code goes in right after the vertex shader loads the vertex's stored position (`POSITION0`), before any of the game's transforms. A variant pipeline is the game's pipeline with only its VS changed, swapped in at `SetPipelineState` exactly as the ports are (E4.2). | Measured over all 2303 dumped VS: the patch applies to 2277, including every VS of every mesh pass (section 4). Every patched container assembles, passes `dxv`, and keeps ISG1 and OSG1. The displacement is a function of the stored position, so every pass that draws the mesh -- depth prepass, shadow, G-buffer, velocity, forward, texture-space paint -- sees the same moved mesh without the patch knowing which pass it is in. |
| A geometry shader appended to each mesh pipeline | **Rejected** (section 14). | It rebuilds world position from clip space through `FC_MatrixInvViewProj`, whose meaning in each view is unmeasured; it leaves outputs stale in 158 stages and does not handle the 103 PntCol VS; it needs a new geometry-visible root table and a `SetGraphicsRootDescriptorTable` detour; and it runs per triangle with no vertex reuse. Its one advantage, 311 compiles against 2277, does not matter: patching is about 3.4 ms per VS (median of the whole chain, one core, native Linux; section 15) and both designs create the same number of pipelines. |
| Lifting DXIL to HLSL and recompiling | **Rejected.** | 1099 of 2303 VS and 155 of 684 materials survive (PATCH). |
| How user HLSL gets into game IR | **A carrier and a splice.** The layer stack is compiled once by DXC into a small `vs_6_0` "carrier"; the helper splices the carrier's IR into each game VS's IR, rewires its inputs and its parameter handle, and reassembles with `IDxcAssembler`. Carriers with branches and loops are spliced by splitting the game's entry block. | DXC has no IR linker for SM 6.0 non-library shaders. The text round trip is lossless: 2303/2303 VS reassemble to identical IR, and dxil-spirv produced byte-identical SPIR-V from original and round-tripped containers in 200/200 samples (50/50 again in review). The V0 prototype measured the splice: seven carriers, including a branch and a loop, each apply to the same 2277 VS and pass `dxv` and rules 1-8 (section 15). |
| The space a layer works in | **V1: the mesh's stored position**, before skinning and before the object's transform. V2 adds a world-space stage. | Object space is proven on 2277 VS and rides along with animation. The world-space insertion point (three `fsub(world, SC_CameraPos.xyz)`) exists in 2135 VS but is not built or validated; world space is what keeps adjacent map pieces from cracking apart. |
| What a layer reads | **Position, time and frame.** No normals, UVs, colours or instance id. | Position is the only input every mesh VS has. `NORMAL0` is a packed `uint` in the measured VS and is decoded differently per shader. |
| Where time comes from | **The parameter block every pass already binds:** `er_p[3].x` now, and a new `er_p[32].x`, the previous present's time. | Velocity passes need both. `cbSceneParam` has no time field (its layout is in every mesh VS's reflection data), and `cbPerFrame`'s `FC_GlobalTime` is bound by only 159 VS. Whether every list of one frame binds the same ring block is unmeasured: gate V0.R1 and oracle F. |
| The unit of selection | **A material group**: every VS whose debug name carries the same material key, in every pass. Selectors pick groups, never passes. | A displacement in some passes only detaches the shadow, the depth prepass and the motion vectors from the visible mesh. Pass sets exist only as a diagnostic in the proof export. |
| Root parameter A | **`b0, space42` becomes `D3D12_SHADER_VISIBILITY_ALL`.** B, C and D stay pixel. | Same cost, 2 DWORDs. The game's raster root signature sets no `DENY_*` flag (RTS0 flags 0x1 in all 5926 raster shaders), and its own shaders never declare space 42. |
| When pipelines switch | **Per group, in one table swap**, once every recorded pipeline of the group has its variant. A pipeline the game creates while its group is live gets its variant synchronously in the creation hook. | The passes of one object must never mix moved and unmoved positions. |
| What gets built | **Lazily:** groups bound in the last 10 s, most-bound first; any other group when it is first bound. | "Everything" is 2277 VS and 8429 pipelines in run1, most of them not on screen. |
| Motion vectors | **Velocity VS get the layer twice:** once at the current time on the current position, once at the previous time on the input their previous-position output reads (`POSITION0`, or `POSITION1` in 40 cloth and hair VS). | Measured 370/370 Velo VS (PATCH). Groups with no velocity VS (314 of 684) get camera-only motion, and their wobble shows as TAA smear. |
| Verification | **Nine rules** (7.4): E7.6's seven for the vertex stage, a residual-identity rule, and a stream rule. | Residual identity proves the patch only added code and redirected the position uses. |
| Proof in game | **AO-port probe oracles**, with lift layers on a time square wave and on frame parity (section 9). No screenshot is judged by an agent. | The AO port already samples depth, the G-buffer normal and the shadow term on an 8x8 grid every frame. |

## 3. The layer the user writes

A vertex layer is one `.hlsl` file with the annotated `uniform`s of E7.2 and one function, attached to the stage `Vertex`:

```hlsl
uniform float Amplitude  < ui_type = "slider"; ui_min = 0.0; ui_max = 0.25; ui_units = "m"; > = 0.03;
uniform float Wavelength < ui_type = "slider"; ui_min = 0.1; ui_max = 10.0; ui_units = "m"; > = 1.5;
uniform float Speed      < ui_type = "slider"; ui_min = 0.0; ui_max = 10.0; ui_label = "Speed (rad/s)"; > = 3.0;

float3 apply(float3 p, VertexCtx c)
{
    float k = 6.2831853 / Wavelength;
    p.x += Amplitude * sin(p.y * k + c.time * Speed);
    p.z += Amplitude * sin(p.y * k * 1.31 + c.time * Speed * 0.77 + 1.7);
    return p;
}
```

**Context** (`shaders/vertex_ctx.hlsli`):

```hlsl
struct VertexCtx
{
    float time;   // seconds: er_p[3].x, or er_p[32].x in a velocity pass's previous-position call
    uint  frame;  // the present count that time belongs to
};
```

- `p` is the vertex as the mesh stores it: model space, in the model's units (metres in FLVER files; not checked per mesh), before skinning. On a character that is the bind pose, so the motion follows the animation. The exception is the `_cloth_` VS: their velocity and fur-direction passes read a previous position from `POSITION1` (45 VS), so their `POSITION0` is a per-frame position, not the bind pose; its space is unmeasured. Every pass of such a group reads the same input, so they still agree with each other.
- `apply` must depend only on `p`, `c` and the layer's uniforms. Velocity passes call it twice, at the current and at the previous time, and a function that read anything else would give wrong motion vectors. No other input exists in a carrier, so this holds by construction.
- `er/noise.hlsli` is available, as in pixel layers. `vertex_ctx.hlsli` defines `ER_VERTEX_CARRIER` before including it, and its `er_fbm` octave loops drop `[loop]` there: dxc records that attribute as `!llvm.loop` metadata, which `vsplice::check_carrier` refuses (measured with dxc 1.9; `tests/reference.rs` compiles every reference entry into a carrier and holds it to the check).

**Composition.** Enabled vertex layers apply in stack order: `p = lerp(p, L::apply(p, c), on * opacity)`, with on and opacity read from the layer slot's header register (E5.2). Toggle and opacity never recompile. Blend modes and stage-local masks do not exist at this stage, and the menu hides them.

**Lint** (E7.5, plus): no texture, buffer, sampler or UAV types; no `register(`; no `SV_` semantics; no `ddx`/`ddy`, wave intrinsics, `min16*` types, `half`, doubles or 64-bit integers; no `precise`, `[loop]` or `[branch]`, which dxc records as metadata on the code (`!dx.precise`, `!llvm.loop`, a control-flow hint) that the carrier check refuses (`[unroll]` and `[flatten]` record none); loop bounds as in P1. The binary checks in 7.3 and 7.4 are the real gate. The Code tab's completion and reference offer a vertex layer none of these, and `VertexCtx`, `ER_TIME_WRAP` and `er_wrap_time` at the vertex stage alone.

**Units and culling.** The game culls with the undeformed bounds, on the CPU and through HiZ on the GPU (`cbSceneParam` carries `SC_HiZTextureSize` and the `SC_OC*` matrices). A displacement that leaves the object's bounds can pop at the screen edge or behind occluders. The amplitude widget says so; how far is safe is unmeasured.

The cache holds 8923 pipelines over 2321 distinct VS, 18 of which were never dumped. 8429 of them use a VS the splice applies to, 8319 of those a mesh-pass VS (the earlier "about 8257 over 2238 distinct VS" was not reproduced). Tessellated water, lava and swamp VS feed a hull shader and write no `SV_Position`; patching `POSITION0` moves their control points, so the domain shader's output follows. Particle pipelines (the 25 with a GS, the 312 FFX tessellated ones) are not meshes and are never selected.

**Why the same object moves the same everywhere:**

1. Every pass of an object reads the same vertex buffer, and its VS gets the same inserted code at the same point, right after `POSITION0` is loaded. Measured: inserting the wobble kept the 543 of 569 main-view name groups whose passes compute `SV_Position` with one expression at 543, and split 0 groups (PATCH, `pos_slice.py`).
2. All passes read the layer's parameters and time from the parameter block bound to their list. The block is captured at each `SetGraphicsRootSignature` (`look_binding.rs` `bind`, `params::current_address()`), so within one frame it is the same block only if no frame's lists are recorded across a present. This is unmeasured: gate V0.R1 measures it, and oracle F proves it in game.
3. Under Proton, vkd3d-proton decorates `SV_Position` `Invariant` in the SPIR-V of all 2274 dumped VS that write it (the other 29 write no `SV_Position`; `scripts/vs-patch/review_invariant.py`), so identical code gives identical positions. The game's own float arithmetic carries `fast` flags in 2280 of 2303 VS, and only one VS has an unflagged `fmul`/`fadd`/`fsub`; the carrier's code is `fast` too, so the patch adds no new class of fast-math risk across passes (`scripts/vs-patch/review_ir.py`). On native D3D12 there is no such guarantee. The game already relies on identical code across its own prepass and G-buffer pipelines, and those still share one patched VS (gate W4).
4. A group switches in one table swap, and a pipeline created while its group is live gets its variant before the creation hook returns (7.5).

**Where it does not hold:**
- A family selector misses the shadow of a group whose shadow is drawn with another group's VS. That applies to the 63 G-buffer groups without their own depth VS, if they cast shadows through the generic `GXFlver_*_Dpt*` VS (unmeasured). "Everything" covers those VS. The selector chip says "this family has no depth shader of its own this session".
- Ray-traced shadows, AO and reflections are built from the vertex buffers, not from the VS, so they see the undeformed mesh. The dump holds 9 DXR libraries; whether ray tracing was on in run1 is unmeasured.
- Normals and tangents are not rotated, so a strongly bent surface keeps its original lighting.

## 5. Motion vectors and shadows

**Motion vectors.**
- 370 Velo and 26 FurDir VS write exactly one output built from `VC_PrevMatrixViewProj` (`b8` registers 29-32) and not from `VC_MatrixViewProj` (24-27).
- Its slice reads `POSITION0` through `cbPrevObjMatrix` in 330 Velo VS, and `POSITION1`, a previous-position stream, in 40 cloth and hair Velo VS and 5 FurDir VS (all 45 carry `_cloth_` in their debug names).
- The splicer inserts a second carrier instance, fed with `er_p[32]` (previous time and frame) and the input that slice reads. It clones the slice after its displaced inputs, iterating to a fixed point because grass and spiderweb VS loop through phis, and points that output's stores at the clones (as `scripts/vs-patch/patch_vs_ll.py --previous` does).
- Measured on 370/370 Velo VS, and by the V0 prototype on 396/396 (370 Velo + 26 FurDir): they assemble and pass `dxv`; the current position is unchanged from the single-instance patch; the previous output reads only the previous time; every other output is unchanged.
- A median of 31 instructions is cloned, p95 44, at most 155.
- Instance 1 reads the current block's layer parameters with the previous time, so a slider edit gives one frame of motion vectors computed with the new parameter on both sides.

`er_p[32].x` is written at publish as the previous block's `er_p[3].x`. It is therefore exactly the time the previous frame's lists used, with the same proviso as point 2 of section 4.

Groups without a velocity VS (314 of 684; FACTS counts 207 of 501 G-buffer material keys) get camera-only motion vectors. TAA and motion blur then see the wobble as unexplained change, and it smears. This is documented in the selector chip; there is no fix inside this design.

**Shadows.** The Dpt and DptA VS of a group are patched with the same code. Wherever the game draws the shadow of a mesh with that mesh's own depth VS, the shadow moves with it. That needs no knowledge of which depth pipelines are shadows. The exceptions are in section 4: generic depth VS, ray tracing, and shadow maps the game may cache across frames (unmeasured). Oracle S measures it in game.

## 7. Runtime path

### 7.1 Records

From V1, every pipeline whose VS debug name is a mesh-pass name gets a `PipelineRecord` (E6.2) at creation. That is 8319 in run1 (8429 counting every pipeline whose VS the splice applies to). `record.rs` already copies every stage's bytecode, interned by length and FNV-1. The deduplicated run1 totals are 35.05 MB of VS bytes and 71.81 MB of PS bytes. `PipelineRecord` gains `with_vs`, a generic per-stage replace on the existing subobject offsets.

A mesh pipeline arriving through `CreateGraphicsPipelineState` is logged and stays vanilla, as E4.1 item 6 does for ports. The 10:48 live log saw 9058 pipelines on the stream path against 8923 in the cache, so the description path is expected to carry none; the count decides.

### 7.2 Root signature

- `appended_1_0` and `appended_1_1` (`look_binding.rs:759`, `:791`) give parameter A `D3D12_SHADER_VISIBILITY_ALL`. B, C and D keep pixel.
- The packed per-root-signature binding gains a bit, "A is vertex-visible". It is set when A is appended to a signature that does not set `DENY_VERTEX_SHADER_ROOT_ACCESS`.
- A vertex variant requires that bit; `Space42Set::admits` gets a per-stage form.
- The DWORD ladder is unchanged.

### 7.3 Building a variant

**Codegen** (`editor/codegen.rs`). One carrier per distinct set of vertex layers that applies to a group, usually one:

```hlsl
#include "vertex_ctx.hlsli"      // er_p at b0, space42, VertexCtx, er/noise.hlsli; no UAVs
namespace L7 { <defines> #line 1 "layers/7-wobble.hlsl" <text> <undefs> }
float3 er_vertex_stage(float3 p, VertexCtx c)
{
    float4 h7 = er_p[ER_P_LAYERS + 7 * ER_P_LAYER_REGISTERS];
    p = lerp(p, L7::apply(p, c), h7.x * h7.y);
    return p;
}
void main(float3 p : ER_POS, float t : ER_TIME, uint f : ER_FRAME, out float3 o : ER_OUT)
{
    VertexCtx c; c.time = t; c.frame = f; o = er_vertex_stage(p, c);
}
```

The carrier is compiled with E7.5's arguments, but `-T vs_6_0 -E main`. It is then checked:
- vertex kind and model 6.0;
- only the three inputs the codegen above declares (`ER_POS`, `ER_TIME`, `ER_FRAME`, each optional, since DXC drops an unread one) and the one output `ER_OUT`;
- resources empty or exactly `CBV b0 space42`;
- SFI0 zero;
- every `dx.op` from an allowlist of pure operations: `loadInput`, `storeOutput`, `createHandle` and `cbufferLoadLegacy` on that handle, unary, binary and tertiary maths, `Bfrev`/`FirstbitLo`-style bit operations, and conversions.

**Splice** (`er-shader-compiler`, new pure module `vsplice.rs`, host-tested). Text in, text out:

1. Disassemble the game VS and the carrier (`IDxcCompiler3::Disassemble`).
2. Find the game's `POSITION0` input element id through `!dx.entryPoints`. Element ids are declaration order, not ISG1 register order. All three `loadInput.f32` columns must sit in the entry block; the insertion point is after the last of them.
3. Add `CBV b0 space42` to `!dx.resources` under a new range id, and create one handle at the insertion point.
4. Insert instance 0 of the carrier:
   - carrier values `%n` become `%er_c0_n`, and labels become `er_c0_bn`;
   - `loadInput(ER_POS, col)` becomes the game's loaded value, `ER_TIME` becomes `er_p[3].x` and `ER_FRAME` becomes `er_p[3].y` bitcast to an integer;
   - the carrier's handle becomes the new one;
   - `storeOutput(ER_OUT, col, v)` defines `%er_x`, `%er_y` and `%er_z`.
5. If the carrier has more than one block, split the game's entry block at the insertion point. The game's remaining instructions move to `er_c0_exit`, and every game phi that names the entry block names `er_c0_exit` instead.
6. Point every later use of the game's x, y and z at `%er_x`, `%er_y` and `%er_z`.
7. For a velocity VS, add instance 1 and the previous-slice clone (section 5).
8. Merge declarations: add the missing `dx.op.*` declarations under an attribute group of identical content (matched by content, never by number), and the missing types.
9. Refuse, leaving the group vanilla, on anything else: no `POSITION0`; position loads outside the entry block or partial columns; no `!dx.resources`; a carrier instruction with a metadata attachment.

**Assemble and sign.**
1. `IDxcAssembler::AssembleToContainer`.
2. `IDxcValidator` with `DxcValidatorFlags_InPlaceEdit`, as a correctness gate.
3. Copy the original's ILDN part in, so diagnostics and the catalogue still name the variant.
4. Set the digest with `dxbc::retail_hash`, which reproduced the validator's digest exactly (PATCH: 0 bytes differ outside offsets 4-20).

**Where it runs.**
- The helper (E7.5) gains two ops, both batched:
  - `Disassemble {blob} -> {text}`;
  - `PatchVertex {carrier, items: [game VS blob], options} -> [{blob, report}]`.

  The report carries the position element id, inserted and cloned instruction counts, the previous-output element id, and rule 8's result.
- LLVM stays in the helper process. The splice is pure Rust in the helper's library, so the in-process fallback runs the same code.
- Patched blobs are cached in memory by (game VS FNV, carrier digest, splice version) and are never written to disk.

### 7.4 Verification before creation (`verify.rs`, vertex rules)

1. **Container.** DXBC magic, total size, part table in bounds, each part once; a DXIL part of kind vertex with the original's model (6.0 in all 2303); at most 1 MiB.
2. **Signed.** Digest nonzero and equal to `dxbc::retail_hash`.
3. **Input linkage.** ISG1 equal to the original VS's, element for element, so the game's `INPUT_LAYOUT` still binds. PSV0 input records equal, matched by (start row, start column) and not by element index: in 481 of 2303 VS the output elements' declaration order (the DXIL signature metadata, which PSV0 follows) differs from register order. OSG1 itself lists elements in register order in all 2303, and no VS's inputs differ (review recount). E7.6's `check_interpolation` pairs by index, which is safe only while both declare in the same order, so the vertex rules must not reuse it.
4. **Output linkage.** OSG1 equal element for element; PSV0 output records, interpolation modes and the position-output flag equal (same matching). The game's PS, HS or DS then link unchanged.
5. **Resources.** Every PSV0 binding is in the original VS's set, or is `CBV b0 space42` on a root signature whose A is vertex-visible.
6. **Features.** SFI0 is a subset of the original VS's.
7. **Root signature.** No RTS0 part; created with the record's own root-signature object.
8. **Residual identity.** Run in the helper, which has the disassembler. Disassemble the variant, then:
   - delete every line that defines an `%er_` value or `er_` block, the added declarations and types, and the added resource node;
   - map `%er_x`, `%er_y`, `%er_z` and the previous-slice stores back to the original values, and `er_c*_exit` back to the entry block.

   What remains must equal the original's disassembly line for line.
9. **Stream.** The variant stream equals the record's in every byte except the VS bytecode pointer and length. Topology type, input layout, HS, DS, GS, PS, rasterizer, depth-stencil, blend, formats and sample description are the game's. Refused if the record has stream output or view instancing: neither occurs in run1 (no `ALLOW_STREAM_OUTPUT` on the raster signature, no VS uses a view id), and the refusal is counted.

The same rules run offline in the prototype and in `tests/` against Linux dxc.

### 7.5 Publish and the bind-time redirect

**Groups.**
- A group's key is the VS debug-name stem with the pass token and the `@[...]` suffix removed, for example `C[c4620]_ClearCoat_Skin`. Run1 has 691 by this definition as the prototype applies it (737 counting non-material VS); FACTS also counted 691 keys and PATCH 684 groups. The 680 written here earlier was not reproduced.
- A group is live when every recorded pipeline of it has a created variant. The worker publishes newly live groups in one table swap.
- When the game creates a pipeline whose group is live, the creation hook creates its variant from the cached patched VS before returning, timed and counted. If p95 exceeds 2 ms, it moves to the worker, and the gap is logged per pipeline.

**Lazy order.**
- While any vertex layer is enabled, the table carries count-only entries for every recorded mesh pipeline. They are not AddRef'd, and they count binds as Hunt entries do (E6.1).
- The worker builds groups bound in the last 10 s, most-bound first, then any group on first bind.
- The UI chip reads "preparing 31/40 groups, 212/540 pipelines".

**Table and hot path.**
- An entry gets `port = VERTEX` and a stage bit `Vertex` in `STAGE_ACTIVE`, which is set while any vertex layer is enabled. E4.2's `set_pipeline_state_hook` is unchanged in shape.
- `cmdlist::note_port_bound` is skipped for vertex entries: they write no probe, owe no barrier, and are redirected on any list type. The census saw no bundles.
- `Reset`, `ClearState` and `CreateCommandList` map their PSO as they do for ports.
- Vanilla and the panic chord pass the game's pipeline through, as for every redirect.

**Graveyard.** A code edit retires every variant of the affected groups, up to 8429 pipelines in run1. The E6.3 cap of 512 entries would leak most of them. An entry becomes a batch: one publish retires one entry holding every pipeline it replaced, and the cap counts entries.

### 7.6 Interplay with the rest of the editor

- **Ports** are full-screen pipelines and never share a VS with a mesh.
- **Masks and picks (P3, P4).** A mask variant (E8.1) or pick duplicate for a pipeline with a live vertex variant is built from the vertex variant's stream. Otherwise mask records sit at the undeformed depth and the coverage oracle fails. When a vertex variant changes, its mask variants are rebuilt and published in the same swap.
- **Hide and blink (P2)** are unaffected.

### 7.7 Parameter block and probe

- `er_p[32]` = `(previous present's time, asfloat(previous frame), asfloat(vertex proof mode), 0)`.
- `er_p[33..63]`: V2's world-space capsule anchors.
- The probe gains a vertex-proof region at `0x1C00`: 64 x 16 bytes of `{asuint(raw depth), asuint(dot(gbuffer normal, depth normal)), asuint(shadow and occlusion term), frame}` on the existing 8x8 grid.
  - The AO port variant writes it when `er_p[32].z` is 1.
  - The depth normal is `normalize(cross(ddx(view_pos), ddy(view_pos)))`, valid because the AO pass is a full-screen pixel pass.
  - The region sits clear of the P4 pick record at `0x1900`.

## 9. In-game proof

The proof is agent-driven through files, like E's P0.2a. Proof layers are staged under `.../Game/er-shader-editor/layers/`, and `check-shader-editor-probe.py`, extended with `--expect vertex-*`, reads the telemetry.

Collapsing vertices to the model origin is not a usable proof: on a skinned mesh each vertex lands on its blended bone origin, so the skeleton's triangles stay on screen. The proof layers lift instead:
- `proof_lift`: `p.y += A` while `frac(c.time / 2) < 0.5`, with `A` a uniform. The mesh steps up and down once a second.
- `proof_lift_parity`: `p.y += A` when `c.frame` is odd.

Skinning rotates the offset, but the rotation is the same in every pass of a frame, so each probe sample's depth takes one of two values in lockstep with the layer. The selector is "everything" unless stated, the player is idle, and A is 0.5 model units unless stated.

1. **Log.** One line per build: `vertex: build <id> carrier=<ms> groups=<live>/<wanted> vs=<n> psos=<n> refused=<n>`, with refusal counts per rule, and `rs: ... vertex_a=<n>` for the root signatures whose A is vertex-visible. Pass: the raster signature is vertex-visible, and patched VS have 0 refusals on rules 1-9.
2. **Oracle D, displacement**, with `proof_lift`.
   - Calibrate for 2 s with the layer off. Geometry samples are probe samples whose depth is not the far plane; the calibration also gives each sample's depth noise.
   - A moving sample is a geometry sample whose mean depths in the up and the down half-periods differ by more than 4 times its noise, in at least 9 of 10 cycles. Skip 2 probed frames after each edge.
   - Pass: at least half the geometry samples are moving with the layer on, and at most 2% in vanilla mode in the same run.
   - Geometry samples that never move are listed with their pipelines from the catalogue, when P2 exists. They are unpatched geometry such as particles, or surfaces the lift slides along.
3. **Oracle F, frame agreement**, with `proof_lift_parity`. This is the decisive oracle for "the same object moves the same in every pass".
   - For each moving sample and frame, compare the depth with the mean of the frames before and after. That classifies the frame as up or down, and is robust to slow camera drift.
   - A frame's state is the majority of its moving samples. A frame is mixed when fewer than 95% of its moving samples agree with the majority.
   - A hole is a sample whose depth is geometry but whose G-buffer normal disagrees with the depth normal (dot below 0.5), at a sample whose calibration dot was above 0.9.
   - Pass, over 600 probed frames: mixed frames <= 1%, and hole samples no more than 0.5% above the vanilla rate measured in the same run.
   - If a frame's prepass and its G-buffer draw bound different blocks, the prepassed objects disagree with the rest (a mixed frame), and the G-buffer draw fails an `EQUAL` test against the prepass depth (a hole). Both are counted.
   - Reported, not judged: the share of frames whose state disagrees with the AO port's own frame parity. That measures whether the lighting list and the geometry lists bind different blocks (the E1 `FRAME_EPOCH` concern), free of charge.
4. **Oracle S, shadows.** A diagnostic export, `er_shader_editor_set_vertex_passes_v1(mask)`, restricts vertex redirects to pipelines whose VS pass token is in the mask. Release behaviour never reads it.
   - Run with `{Dpt, DptA}` only and `proof_lift` at A = 50, which carries every shadow caster's shadow far from where it was.
   - Pass: at least 4 samples keep their depth (relative change below 1e-4) while their shadow term changes by at least 0.2, in phase with the layer (correlation at least 0.9).
   - Fewer than 4 samples in shadow during calibration is inconclusive, not a failure. The user is then asked for an outcome: a sunlit view with shadows across the screen.
   - The same run reports whether moving only the depth pipelines changes main-view depth or opens holes. That answers which depth pipelines are a main-view prepass, the FACTS open question.
5. **Motion vectors.**
   - Offline, the structural check on every velocity VS (prototype item 6) proves them.
   - In game, Velo and FurDir variant binds per frame must be above 0 while a velocity group is on screen. That is a hook counter, not a pixel measurement.
   - No port reads the velocity target, so the effect on TAA has no oracle in V1, and the report says so.
6. **Oracle C, cost.** The `wobble` template runs on everything while the export toggles the vertex stage every 60 frames. The mean frame-time change is reported. Target: <= 0.5 ms in the census scene; unmeasured until then.
7. **Vanilla.** `set_mode(1)` makes the redirected-binds delta 0 for vertex entries, and oracle D finds no moving samples.

## 12. Risks

1. **Per-frame time agreement is unmeasured** (R1, oracle F). If a frame's lists straddle a present, a prepass and its G-buffer draw can bind different times, which opens holes wherever the game tests `EQUAL`. Static deformations are unaffected.
2. **The splice is measured offline only.** The V0 prototype passes items 1-11 on run1 (section 15); nothing has run in a game.
3. **Pipeline creation** for thousands of variants is unmeasured on vkd3d and on native drivers. Under vkd3d-proton it is a synchronous translation and Vulkan compile inside `CreatePipelineState` (section 8), on the worker or, for a pipeline the game creates while its group is live, on the game's creating thread. The lazy order bounds the work to what is on screen.
4. **Shadows drawn with another group's VS.** For the 63 G-buffer groups without their own depth VS, a family selector may miss their shadow (section 4).
5. **Ray tracing** sees the undeformed mesh (R4).
6. **Culling** uses undeformed bounds on the CPU and through HiZ; large amplitudes pop.
7. **Normals are not rotated**, so lighting stays the undeformed surface's.
8. **TAA smear** on the 314 of 684 groups without a velocity VS.
9. **Native D3D12** gives no invariance guarantee across pipelines. Shared VS bytes keep the prepass case as safe as the game's own; W4 tests the rest.
10. **The dxcompiler licence** (E15 risk 2) also covers the assembler and validator.
11. **Memory**: about 107 MB of records in run1, more in a longer session. A bytecode-residency measurement could drop the copies later (E14 waits).
12. **Run1 is one session.** Groups seen later are patched at runtime, lazily, and nothing is pinned by hash. A game update that changes the VS IR shape shows up as refusal counts, not as wrong pixels.
13. **One-frame mismatches** at a table swap mid-frame, and when the user edits a layer.
14. **Time is the editor's present clock**, not the game's, so the wobble keeps moving while the game is paused.

## 14. Rejected

| Approach | Why |
|---|---|
| A geometry shader appended to every mesh pipeline | It sees only clip space and must rebuild world position through `FC_MatrixInvViewProj`, unmeasured per view. Its own plans leave something stale in 158 stages (Pnt 125, clip distances in 14 Fwd and 19 tessellated domain shaders) and do not cover 162 (PntCol and others). Its velocity seed is the current world position, an approximation. It needs a geometry-visible mirror of VS table 1 plus a new `SetGraphicsRootDescriptorTable` detour (call rate unmeasured). It runs once per triangle with no post-transform reuse, and has triangle-input variants only. Its saving -- 311 compiles instead of 2277 -- is about 7 s of helper time on one core (section 8), and both designs create the same pipelines. |
| Lifting DXIL through dxil-spirv and SPIRV-Cross to HLSL | 1099/2303 VS survive every check with an identical position expression, and 155/684 whole groups. Losses: 948 OSG1 rows that pack two semantics, 139 clip-distance shapes, 92 changed position expressions, 23 overlapping resource ranges. |
| Switching on the game's own deformation inputs | SpeedTree wind (`b13`, 110 VS), the force field (`t26`, 40 VS), vertex-animation textures (65 VS) and cloth-cancel palettes (527 VS) exist only in the VS that already read them. Using them anywhere else means replacing that VS anyway. |
| Displacing in some passes only | Detaches the shadow, the depth prepass and the motion vectors from the visible mesh. Kept only as the diagnostic pass mask in oracle S. |
| Hand-ported replacement VS, like the five pixel ports | 2303 dumped VS (2321 referenced by the cache) and no source. |
